## Решения владельца (не менять без согласования)

- Торгуем **с прибылью по цене, близкой к минимальной**. Минимальная = цена, которую реально платит покупатель
  после всех скидок (акция Ozon + наша акция), и при ней прибыль ≥ заданного минимума.
- **База прибыли:** рыночная цена (`OZON_PERC.AVAILABLE_PRICE`) → иначе средняя цена приходов → иначе товар
  не считать и показать «нет базы». **Максимальный приход не использовать никогда.** Подставлять 1 ₽ нельзя.
- **Акции:**
  - товар в акции Ozon → цена после скидки Ozon **плюс** скидки нашей акции = минимальная; нашу скидку держать на минимуме;
  - товар только в нашей акции → цена после нашей скидки = минимальная;
  - товар не в акциях → пробуем добавить в акцию Ozon (правило 1), не берут — добавляем в нашу (правило 2).
    Наша акция нежелательна (скидки суммируются), но без неё не продать близко к минимальной.
- **Проверяем все товары кабинета**, а не только товары в акциях.
- **Схема FBO/FBS:** считаем по худшей (меньшая прибыль) из схем, где у товара есть остаток.
- **Ценовые ступени Ozon:** товаров до 100 ₽ нет. Сначала считаем по ставкам «100–300»; если цена ≤ 300 —
  берём её; иначе считаем по ставкам «свыше 300».
- **Логистика:** FBS отгружаем из кластера **Новосибирск**. Направление доставки — **по реальным заказам**
  (взвешенное среднее). Сейчас в коде среднее min/max из API — это fallback, когда истории нет.
- **Кр (коэффициент снижения логистики за локальность) не учитываем** — считаем по предельному тарифу.
- **Возвраты:** процент **возвратов** (не отмен!) по артикулу, хранить в `OZON_PERC`, считать автоматически;
  без истории — 0 %.
- **Тарифы:** XLSX логистики и комиссий Ozon меняет еженедельно. Загружаются **через админку**;
  если файл старше 7 дней — **напоминание в бот Matrix (тема PRICES)**.

## Этап 3. База прибыли (себестоимость)

Сейчас (`src/trade2006.good/trade2006.good.service.ts`, запрос с `PRIC`): средневзвешенная по остатку → MAX(AVAILABLE_PRICE)
→ последний приход → **1**. Последний fallback «1» опасен.

## Этап 6. Единый расчёт минимальной цены

Одна чистая функция (без запросов наружу): вход — база, наценки, % рекламы, упаковка, этикетка, обработка, налог,
ставки комиссии по ступеням и схемам, логистика по ступеням и схемам, последняя миля, эквайринг, % возвратов,
мин. прибыль (₽) и мин. наценка (%), суммарная скидка акций. Выход — min/норм/макс цены, прибыль на каждой,
разложение расходов, источник базы.

- Ступени: считаем по «100–300»; результат ≤ 300 — берём; иначе по «свыше 300». Если на следующей ступени
  расходы ниже и цена «проваливается» под её границу — ставим границу + 1 ₽.
- Схема: считаем FBO и FBS (если есть остаток FBO), берём худшую.
- Прибыль ≥ max(мин. прибыль ₽, мин. наценка % × база).
- Заменить ею: `calculatePrice`/`calculatePay` для Ozon, `optimizeOzonPrice`, расчёт в profit-check.
- Тесты: таблица примеров с ручным пересчётом (в т.ч. 560209-1: база 63,35, комиссия 51 %, логистика API).
